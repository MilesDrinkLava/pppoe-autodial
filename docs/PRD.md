## 1. 背景与痛点

校园网/部分宽带用户上网需要 **PPPoE 宽带拨号**。Windows 不会在开机后自动拨号，用户每次开机都要手动点一遍：

- 右键拨号连接 → 连接 → 等待验证……繁琐且每天重复
- 想打游戏/开工时发现"怎么没网"，才想起来还没拨号

现有替代方案的问题：

| 方案 | 问题 |
|---|---|
| 拨号属性勾"自动连接" | 只有少数场景有效，对 PPPoE 开机场景基本不可靠 |
| 第三方拨号助手/校园网工具 | 体积大、常驻后台、部分带广告或捆绑，来源不透明 |
| 手动写个脚本 | 可行但缺少：凭据安全存储、失败重试、开机集成、状态检测等细节，普通用户难落地 |

**本项目的价值：用最少的系统原生组件，把"开机自动拨号"做对、做稳，并保持轻量、透明、无依赖。**

## 2. 产品定位

> 一个零依赖、无后台进程的 Windows 小工具：登录系统后自动完成 PPPoE 拨号，凭据加密存储，失败自动重试，全过程留日志。

**非目标（明确不做）**：

- ❌ 不做校园网 Web 认证（Portal 登录）替代——那是与 PPPoE 完全独立的另一套体系
- ❌ 不改动/劫持用户现有拨号配置
- ❌ v1 不做跨平台（Linux 下 PPPoE 的自动拨号属系统配置范畴，思路完全不同）
- ❌ 不常驻后台、不驻留托盘（保持零进程开销；断线重连用任务计划重复触发实现）

## 3. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 校园网宿舍用户 | 有线口 PPPoE 拨号，每天开机第一件事 |
| 电信/联通/移动宽带用户 | 光猫桥接 + 电脑拨号（玩家、极客常见配置） |

典型使用旅程：创建连接（一次性）→ 部署本工具（一次性）→ 此后每次开机自动联网。

### 4.1 技术方案与关键决策（含踩坑记录）

**架构（零常驻进程）**：

```
任务计划 (AtLogOn, 限定用户)
  └─ powershell -WindowStyle Hidden dial.ps1
       ├─ 读取 cred.dat → DPAPI 解密（明文仅存在于内存变量）
       ├─ 等待 3s → 检测 PPPoE 接口是否在线（是 → 退出）
       ├─ rasdial 拨号 → 失败每 5s 重试（上限 12 轮）
       └─ 全程写 dial.log
```

**决策记录**：

1. **为什么用 `rasdial` + 任务计划，而不是常驻守护进程**
   系统原生、零依赖、零后台开销；任务计划本身提供开机触发、失败重启、电池策略等成熟能力。最少的活动部件 = 最高的稳定性。
2. **为什么凭据用 DPAPI 文件（cred.dat）**
   不落明文；只有当前用户+本机能解密；比"明文写脚本"安全。不选凭据管理器（cmdkey）是因为其对 RAS 凭据的支持不可靠。
3. **为什么用接口状态判断在线，而不是 ping/开网页测试**
   电脑可能同时连 Wi-Fi，流量未必走 PPPoE；校园网常禁 ICMP。`Get-NetIPInterface` 查的正是"这个 PPPoE 会话在不在"，语义精确、无副作用。⚠️ 注意：PPPoE 接口不出现在 `Get-NetAdapter` 里，必须用 `Get-NetIPInterface`（坑）。
4. **为什么脚本全英文书写**
   PowerShell 5.1 读取无 BOM 的 UTF-8 脚本时中文会乱码，可能导致解析异常。规避成本最低的做法：脚本与日志全英文，文档用中文。
5. **为什么重试上限是 12 × 5s ≈ 1 分钟**
   覆盖开机时网卡/交换机端口未就绪的极端情况（交换机 STP 收敛最长可达 30s+）；又有明确上限，不会无限重试。
6. **为什么用 Interactive + Limited 权限运行**
   拨号不需要管理员；隐藏窗口 + 普通权限 = 用户零感知、不弹 UAC、安全性最佳。⚠️ 实测普通权限即可注册任务（无需提权）。
7. **工具链坑（供维护者警戒）**
   - Git Bash（MSYS2）调用 Windows 原生命令时参数可能被路径转换搞坏（如 `rasdial /disconnect` 假成功、退出码 0 但未执行）。**一切拨号相关操作在 PowerShell 中执行，并用状态验证而非退出码**。
   - "先断开再验证自动拨号"的测试必须**确认接口真的消失/断开**，否则整轮验证无效（曾因此浪费排查时间）。
8. **为什么图形安装用系统原生对话框**
   MessageBox / InputBox 等系统自带组件——零依赖、零体积、立刻可用。向导全程 6 次交互完成部署。密码以明文输入（个人单机场景，可视输入便于核对）。
9. **为什么掉线守护选择"任务计划重复触发"而非常驻进程**
   资源预算：默认每 15 秒（可配置，最小 10 秒）启动一个存活约 0.6 秒的隐藏脚本进程（检测到在线即退出，实测 CPU 时间约 0.2 秒/次），平均 CPU 占用约 0.2%（八核口径），无内存常驻。**实现细节**：任务计划服务强制重复间隔 ≥1 分钟（实测 PT15S 被拒，错误 0x80041318），因此短于 1 分钟的间隔通过 N 个错峰触发器实现（N = 60/间隔秒数，每个触发器每 1 分钟重复、起始点错开）——纯调度技巧，不引入常驻进程。不运行时不存在的进程 = 不可能造成卡顿。常驻进程方案（30~60MB 内存）与事件监听方案（RAS 事件通知不可靠）均被否决。守护为可选功能，**默认关闭**，安装时可勾选。
10. **为什么用 VBS 静默启动器（dial-hidden.vbs）**
    实测发现：任务计划直接启动 `powershell.exe` 时，`-WindowStyle Hidden` 挡不住控制台窗口"先创建后隐藏"的瞬间，守护模式下每 15 秒闪现一次黑框。改为 `wscript.exe`（GUI 宿主，无控制台）+ VBS `Run(..., 0)` 以 SW_HIDE 启动——窗口从进程创建起即隐藏，彻底消除闪现（实测运行中进程 MainWindowHandle = 0）。另配 `//B` 参数抑制脚本错误弹窗。

### 5.1 FR-9 图形安装向导 · 交互设计

全部使用系统原生对话框（MessageBox / InputBox / WinForms 掩码窗口），零第三方依赖、零安装体积：

```
步骤 1  自动检测：解析 rasphone.pbk（用户级 + 系统级）找出所有 PPPoE 连接
        ├─ 0 个 → 错误框：提示先创建宽带连接
        ├─ 1 个 → 确认框："检测到拨号连接【X】，配置为开机自动拨号？"
        └─ 多个 → InputBox 列出编号供选择
步骤 2  InputBox 输入宽带账号
步骤 3  InputBox 输入密码（明文显示——个人单机场景，可视输入便于核对、降低输错率）
步骤 4  询问："是否启用掉线自动重连？"（默认按钮 = 否，默认关闭）
步骤 5  （若启用）InputBox 设置检测间隔（默认 15 秒，最小 10；无效输入回退 15 并提示）
步骤 6  静默执行：写 config.ps1 → 生成 cred.dat（DPAPI）→ 注册任务
步骤 7  询问："是否立即断线测试（约 10 秒）验证账号密码？"（默认否）
        └─ 是 → 断开 → 触发任务 → 等待 → 结果框（成功 / 失败原因）
步骤 8  完成框：部署摘要 + 管理入口（暂停恢复.cmd / 卸载.cmd / dial.log）
```

工程约束：含中文 UI 文案的脚本**必须以 UTF-8 with BOM 保存**（PS 5.1 读无 BOM UTF-8 中文会乱码）；`dial.ps1` 等无 UI 脚本保持全英文。
